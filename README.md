# DCF valuation model

[![CI](https://github.com/ParBproject/dcf-valuation-model/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/ParBproject/dcf-valuation-model/actions/workflows/ci.yml)

A discounted-cash-flow model for AAPL, MSFT, KO, JNJ, CAT and XOM. Financials come from SEC EDGAR companyfacts, prices from Yahoo Finance, the risk-free rate from FRED DGS10, and the equity risk premium from Damodaran. Inputs are saved as a dated snapshot, so the valuations can be rebuilt offline.

Python writes `results/valuations.json`. A TypeScript port of the same model runs in the browser: assumption sliders, a WACC × growth heatmap, Monte Carlo, a reverse DCF, and drill-downs back to the 10-K tag. [Live demo](https://parbproject.github.io/dcf-valuation-model/).

This is a modelling exercise, not investment advice.

## Model

- **FCFF** = EBIT × (1 − tax) + D&A − capex − ΔNWC. Revenue growth fades from the 6-year CAGR to terminal g over 10 years. EBIT margin reverts to the 6-year mean.
- **WACC** uses market-value weights. Cost of equity is the risk-free rate plus a Blume-adjusted regression beta (5-year monthly returns vs the S&P 500) times Damodaran's ERP. Cost of debt is interest / debt, floored at the risk-free rate.
- **Terminal value** is NOPAT × (1 − g / ROIC) grown one year and capitalized, with ROIC at 15%. An exit EV/EBITDA multiple is only a cross-check.
- **Equity value** is enterprise value minus debt (CAT: net of finance receivables) plus cash and short-term investments, divided by diluted shares.
- **Risk.** WACC × g grid, one-at-a-time driver shocks, 10,000 Monte Carlo draws (seed 20261022), and a reverse DCF for the growth that matches the market price.

Sources and dates are in [SOURCES.md](SOURCES.md). Per-ticker tagging gaps are listed in each `config/<TICKER>.yaml` and shown in the app.

**Limits.** One snapshot, month-end prices, and the same rules for every company. No segments and no analyst estimates. XBRL gaps use the proxies noted per ticker. CAT's captive-finance netting assumes the receivables roughly match the debt that funds them. The Monte Carlo moves four drivers and draws them independently.

## Run

```
make install && make check    # ruff + pytest, offline, against the committed snapshot
make results                  # rebuild valuations.json, TypeScript fixtures, README assets
cd web && npm ci && npm test && npm run build
npm run e2e && npx playwright test
```

`make snapshot` refreshes inputs from the network. Set `SEC_USER_AGENT` to `"Your Name you@example.com"` first. If it is unset, requests use `Par Bahrae githubproproject@proton.me`. GitHub Actions reads the `SEC_USER_AGENT` repository secret.

After a model change: `make valuations && python scripts/export_engine_fixtures.py`, then `cd web && npm test`.

## Layout

```
src/dcf/data       SEC companyfacts, prices, rates, snapshot writer
src/dcf/model      FCFF, forecast, WACC, terminal value
src/dcf/analysis   sensitivity, Monte Carlo, reverse DCF, results writer
data/snapshots     dated inputs
results            model output
web                React app
```

The web app reads `web/public/data/valuations.json`, copied from `results/` by `npm run sync-data`. That copy is gitignored.

Vitest checks the TypeScript port against exported Python cases to within 0.01%. The browser Monte Carlo uses a different random generator, so the match is statistical (see `web/src/engine/mc.test.ts`). Playwright covers axe, keyboard, mobile layout and visual baselines. A Lighthouse run on 2026-10-23 is in [docs/lighthouse/summary.json](docs/lighthouse/summary.json): performance 91–94 on mobile and 100 on desktop for the pages listed there, with CLS 0.

GitHub Pages serves the `gh-pages` branch. `npm run deploy` (`scripts/deploy_pages.sh`) builds `web/` and pushes `dist/` there.
